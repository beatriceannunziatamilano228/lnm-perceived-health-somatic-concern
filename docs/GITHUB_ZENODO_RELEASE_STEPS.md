# GitHub and Zenodo release steps

1. Create a private GitHub repository and upload the contents of this folder.
2. Confirm that no participant-level `.mat` files are present.
3. Confirm permission to redistribute the historical group-level NIfTI; remove it if uncertain.
4. Add the final GitHub repository URL to `docs/CODE_AVAILABILITY_STATEMENT.md`.
5. Connect the repository to Zenodo, create release `v1.0.0`, and archive it.
6. Add the Zenodo DOI to `CITATION.cff`, the README and the manuscript.
7. Do not alter the tagged release after manuscript resubmission; create a new tag for changes.
